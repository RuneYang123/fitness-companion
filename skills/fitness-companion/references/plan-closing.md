# 完整计划的结尾

## 使用时机

用户在所需模块结束后选择最终清单，或明确确认采用所需计划、准备开始执行时，在最终总清单后附上下面的作者结尾一次。用户只需要训练等部分模块时，以其所需内容完成为准，不强迫补齐训练、饮食、补剂和睡眠。

| 当前情形 | 是否附加 |
|---|---|
| 仍在逐项看模块、选择下一步或修改计划 | 不附加，继续处理当前内容 |
| 最后一个模块刚结束，用户尚未选择下一步 | 正常输出该模块，提供修改或整理最终清单的选择，不立即汇总或附结语 |
| 用户在流程末尾选择“给我最终清单”等 | 同一回复给最终总清单及作者结尾一次，不再额外要求确认 |
| 已完成所需内容，并说“就按这个来”“这些够了，我先练练”等 | 附加一次 |
| 只回复“好的”“可以” | 结合上下文判断；不能仅凭这两个词认定整份计划结束，也不机械追问是否结束 |
| 查动作、看每日清单、反馈、调整一餐或一次训练 | 不附加 |
| 换聊天接续、导入或导出同一份计划 | 不重复附加，换聊天不重新计算次数 |
| 日后重新制定一份完整计划，并确认采用 | 可以再次附加一次；局部修改不算重新制定 |

模块刚结束时，先正常输出当前模块及修改或整理清单的选择，不自动重发其他模块。用户选择最终清单或明确采用整份计划后，顺序为：按[计划总清单](plan-summary.md)列出本次具体安排和必要说明，合适时提供一次可选的接续记录入口，最后放作者结尾；不在结尾后继续追加模块选择或制作说明。用户专门要求预览结尾时可直接展示，不必重发计划，也不视为正在完成健身计划。

完整保留作者原文与排版，包括P.S.；仅检查文字错误，不自行润色、缩写或改换措辞。结尾中的鼓励不取代具体的不适处理；不能让用户等智能体回复再处理异常。

## 结尾文案

朋友，看到这里，属于你的计划就已经打造完毕了。接下来的主角是你——毕竟，真正去流汗远比一份完美的计划重要得多。先去练上一阵子，途中遇到任何卡壳的地方，随时回来找我聊。

其实做这个 Skill 的初衷很简单。刚接触健身那会儿，我们很容易在海量的自媒体教程里迷路：今天看一个练肩秘籍，明天存一个练背干货。但那些碎片化的大众模板，拼不出一个完整的你，也没法真正解决你当下的痛点。

诚然，**这个 Skill 终究只起到一个辅助作用，它给的计划绝不是唯一的标准答案。** 它更像是一块敲门砖，先给你搭好思路、带你找到训练的节奏。等你慢慢练出自己的体感了，随时可以按自己的想法去改，或者带着身体的反馈回来找我，我们一起迭代、共同进步。

在正式开练前，还有几条铁律想额外叮嘱你：

- **保护关节永远第一：** 一旦感觉关节有不对劲的不适感，必须尽早处理，或者立刻来问我，绝不要带伤硬顶。
- **动作规范大于盲目冲重量：** 任何花里胡哨的“邪修”技巧，都不如你主动降低一点强度、老老实实把动作做标准。
- **睡眠和休息比锻炼更重要：** 训练只是给身体发信号，真正的恢复和变强，全靠你睡好、歇好。
